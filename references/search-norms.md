# 搜索规范汇总

本文档汇总深度研究中的搜索规范，供参考和引用。

---

## 一、任务分类

### 任务类型判定

| 模式 | 特征 | 研究深度 | 示例 |
|------|------|----------|------|
| **快速事实查询** | 单一问题，最短路径 | 浅层 | 某公司 CEO 是谁？ |
| **当前动态查询** | 获取最近变化 | 浅层-中层 | 某法规是否更新？ |
| **实体研究** | 围绕实体综合检索 | 中层 | 某公司产品路线 |
| **深度研究** | 多维问题，跨来源 | 深层 | 某行业竞争格局 |
| **核查/证伪** | 判断说法是否成立 | 中层-深层 | 某 API 是否已弃用？ |

## 二、时效性判定

### 必须联网核验的信息

凡是**有超过 10% 概率已变化**的信息，必须联网核验：

| 信息类型 | 变化频率 | 核验要求 |
|----------|----------|----------|
| 新闻、事件 | 极高（天/周） | 必须核验 |
| 价格、优惠 | 高（周/月） | 必须核验 |
| 人物职位 | 中高（月/季） | 必须核验 |
| 产品规格、版本 | 中（月/季） | 建议核验 |
| 法规、政策 | 中低（季/年） | 建议核验 |
| 学术知识 | 低（年/十年） | 可选核验 |
| 历史事实 | 极低 | 无需核验 |

### 时效性判断流程

```
1. 判断信息类型 → 确定变化频率
2. 查看来源时间 → 判断是否在时效窗口内
3. 若超时 → 必须重新搜索
4. 标注时效性边界 → 在输出中说明
```

## 三、证据链规范

### 来源分级体系

```
级别 1：官方/原始
├── 官方公告、新闻稿
├── 官方文档
├── 法规原文
├── 论文原文
├── 招股书、年报、财报
└── 监管机构文件

级别 2：权威机构
├── 研究机构报告
├── 专业出版社
├── 监管机构公告
└── 行业协会报告

级别 3：主流媒体
├── 高质量新闻媒体
├── 专业数据库
└── 知名博客/专栏

级别 4：二手来源
├── 转引、摘要
├── 一般博客
└── 社交媒体转载

级别 5：社交/论坛
├── Twitter/X
├── Reddit
├── 论坛帖子
└── 用户评论
```

### 证据链要求矩阵

| 结论风险 | 来源数量 | 来源类型要求 | 示例 |
|----------|----------|--------------|------|
| **低** | ≥1 | 高可信（1-3级） | 某产品发布时间 |
| **中** | ≥2 | 其中≥1个官方/原始 | 某公司融资情况 |
| **高** | ≥2-3 | 必须含原始来源 | 某政策影响判断 |

### 社交平台使用规则

```
✅ 可用场景：
- 发现线索和话题
- 了解舆论动向
- 获取实时信号

❌ 禁用场景：
- 作为唯一结论依据
- 未经核验直接引用
- 用于高风险决策

⚠️ 必须行为：
- 回查官网、媒体或原始文件
- 标注"来自社交平台，需核验"
- 说明可信度限制
```

## 四、来源冲突处理

### 冲突识别

当出现以下情况时，判定为来源冲突：

- 不同来源对同一事实给出不同说法
- 来源 A 和来源 B 的数据不一致
- 时间线或事件描述存在矛盾

### 处理流程

```
Step 1: 识别冲突点
├── 确定具体哪个事实有分歧
└── 明确分歧的具体内容

Step 2: 记录各方说法
├── 来源 A 的说法
├── 来源 B 的说法
└── 其他相关来源

Step 3: 比较来源质量
├── 发布时间
├── 来源类型
├── 可信度等级
└── 内容完整性

Step 4: 形成判断
├── 明确倾向（如有）
├── 说明判断依据
└── 标注不确定性

Step 5: 输出说明
├── 在报告中使用冲突模板
└── 在限制与边界中总结
```

### 判断原则

```
优先级排序：
1. 官方来源 > 非官方来源
2. 原始来源 > 二手来源
3. 最新来源 > 较旧来源
4. 权威来源 > 一般来源
5. 详细来源 > 简略来源
```

## 五、不确定性披露

### 必须披露的场景

| 场景 | 描述 | 示例 |
|------|------|------|
| **来源冲突** | 多个来源说法不一致 | A 来源说营收 50 亿，B 来源说 45 亿 |
| **单一非官方来源** | 仅有一个非官方来源 | 仅有媒体报道，无官方确认 |
| **信息缺失** | 无法获取关键信息 | 页面不可访问、需登录、未公开 |
| **时效性问题** | 信息可能已过时 | 来源时间为 2 年前 |
| **推断性结论** | 结论依赖推断 | 基于趋势预测未来 |

### 披露格式

```markdown
⚠️ 不确定性说明

**不确定点**：[具体内容]
**原因**：[为什么不确定]
**影响范围**：[对结论的影响]
**建议**：[如何进一步核验]
```

## 六、查询设计规范

### 查询改写矩阵

| 查询类型 | 目的 | 模板 | 示例 |
|----------|------|------|------|
| **精确查询** | 完整表达问题 | `[完整问题]` | `current CEO of OpenAI` |
| **召回查询** | 高信号关键词 | `[实体] [关键词]` | `OpenAI CEO` |
| **官方查询** | 找官方入口 | `site:[官方域名] [关键词]` | `site:openai.com leadership` |
| **时效查询** | 找最新信息 | `[主题] [年份] update` | `GPT-4 2026 update` |
| **交叉查询** | 多维度验证 | `[主题] announcement site:[官方域名]` | `GPT-5 announcement site:openai.com` |

### 场景化查询模板

#### 当前职位/持有人
```
current [角色] of [组织]
site:[官方域名] [组织] leadership
"[角色]" "[组织]"
```

#### 新闻/最近动态
```
[主题] latest news
[主题] [当前年份] update
[主题] announcement site:[官方域名]
```

#### 产品/规格/价格
```
[产品名] official specs
[产品名] price official
site:[厂商域名] [产品名]
```

#### 技术/API/版本
```
[功能] official documentation
[产品] release notes
[产品] deprecation site:[文档域名]
```

#### 法规/标准
```
[法规/标准号] official text
site:[监管机构域名] [主题]
[主题] guidance official
```

### 查询拆分规则

遇到复合问题时，先拆子问题：

```
原问题："比较 A 公司和 B 公司过去一年的产品发布、融资动态和监管风险"

拆分为：
1. A 公司产品发布
2. B 公司产品发布
3. A 公司融资动态
4. B 公司融资动态
5. A 公司监管风险
6. B 公司监管风险
7. 综合对比分析
```

## 七、PDF/图表处理

### 处理原则

```
原则 1：纯文本优先
├── 能用文本抽取 → 优先文本
└── 无需视觉确认

原则 2：视觉确认必要场景
├── 图表、图形
├── 复杂表格
├── 扫描件、图片
└── 非结构化布局

原则 3：禁止假设
├── 不假设"文本已完整"
├── 不假设"图表不重要"
└── 不假设"表格可还原"
```

### 处理流程

```
1. 判断 PDF 内容类型
   ├── 纯文本 → 文本抽取
   ├── 含图表/表格 → 视觉确认
   └── 扫描件 → OCR/视觉确认

2. 视觉确认方式
   ├── browser 截图
   ├── PDF 转图片
   └── 手动查看

3. 数据引用规范
   ├── 优先引用表头、单位、注释
   ├── 标注数据来源页码
   └── 注明"已视觉确认"
```

## 八、质量验收

### 验收清单

#### 正确性
- [ ] 回答了用户真正的问题
- [ ] 时间范围、主体、地区无误
- [ ] 没有把旧闻说成新动态

#### 来源支撑
- [ ] 每个核心结论都有来源
- [ ] 高风险结论有原始来源
- [ ] 没有把社交平台当作唯一依据

#### 时效性
- [ ] 易变信息已联网核验
- [ ] 使用了足够新的来源
- [ ] 当前职位、价格、规则、版本已确认

#### 表达边界
- [ ] 事实、推断、建议分开
- [ ] 冲突来源已说明
- [ ] 证据不足处已明确写出不确定

#### 成本控制
- [ ] 没有无意义重复搜索
- [ ] 先 API 后 crawl，先 HTTP 后 browser
- [ ] 已达到停止条件后未继续扩搜

## 九、工具路由参考

### 路由策略

```
按复杂度路由：
├── 简单查询 → quick-web-search (SearXNG)
├── 深度研究 → deep-search-research
├── 复杂页面 → agent-browser
├── 难抓取网页 → scrapling-plus
└── 社交平台 → opencli-bridge

按风险路由：
├── 低风险 → 单一来源即可
├── 中风险 → 多来源 + 时效核验
└── 高风险 → 原始来源 + 冲突处理
```

### 协作参考

| 场景 | 推荐技能 |
|------|----------|
| 快速查证、RSS 监控 | `quick-web-search` |
| 复杂页面、JS-heavy、登录态 | `agent-browser` |
| 难抓取网页、反爬绕过 | `scrapling-plus` |
| 社交平台数据 | `opencli-bridge` |
